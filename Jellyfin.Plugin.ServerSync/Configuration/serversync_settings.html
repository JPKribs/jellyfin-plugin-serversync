How long an item must go untouched after its last change before that change is sent to the servers in Push or Sync mode. Every further edit restarts the wait, and one update goes out at the end of it, so a poster changed twice a minute apart is sent once. Default: 60.
How long to wait before sending a change again when a peer gives no answer or answers with an error. Each further failure doubles the wait. Default: 30.

How long sending to a peer pauses after it refuses this server's key or does not have Server Sync installed. Default: 15.
How many times a change is sent to a peer that keeps refusing before it is marked failed. 0 keeps trying until the peer answers. Default: 0.

Troubleshooting

Resets for the tracking tables. A reset forgets what has been compared and synced, not the media, and the next run rebuilds the table from the servers.
Reset individual sync tables or the entire database. These actions are destructive and cannot be undone.

Reset Individual Tables

Content Sync
Remove all content tracking data. Content will need a rescan.
History Sync
Remove all history tracking data. History will need a rescan.
Metadata Sync
Remove all metadata tracking data. Metadata will need a rescan.
User Sync
Remove all user sync tracking data. Users will need a rescan.
People Sync
Remove all people sync tracking data. People will need a rescan.

Reset Entire Database

Full Database Reset
Delete the entire sync database file and recreate it from scratch. All tracking data across all sync types will be lost.
